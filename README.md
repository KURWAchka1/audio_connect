# Audio Connect

Звук Windows-компьютера на Android-телефоне по USB-кабелю. Компактные нативные приложения без учётной записи, рекламы и облачных серверов.

**[Скачать установщик и APK](https://github.com/KURWAchka1/audio_connect/releases/latest)**

- Windows 10 1809+ / Windows 11, x64. Установщик ставит приложение для текущего пользователя, без прав администратора; .NET и ADB входят в комплект.
- Android 7.0+ (API 24), универсальный подписанный APK без зависимости от Google Play Services. Android 17 учитывается через запуск `mediaPlayback` foreground service из видимого экрана; физический Galaxy S24 не тестировался.
- Стерео PCM 16 bit / 48 кГц без сжатия, около 193 кБ/с. Wi-Fi, USB-модем, root и виртуальный аудиодрайвер не нужны.
- Буфер 20 / 40 / 80 мс, автоматическое восстановление кабельного соединения и воспроизведение с выключенным экраном.
- Цифровое усиление 0…+12 дБ, связанный стереолимитер с 5 мс lookahead и потолком −1 дБFS. По умолчанию усиление выключено, срез баса ниже 120 Гц включён.

## Подключение

1. Установите `AudioConnect-Setup-1.0.0-win-x64.exe` на ПК и `AudioConnect-1.0.0-android.apk` на телефон. Для APK разрешите установку из того приложения, откуда открываете файл. APK подписан постоянным ключом проекта; обновления с тем же ключом устанавливаются поверх него.
2. На Samsung: **Настройки → О телефоне → Сведения о ПО → Номер сборки**, нажмите 7 раз. Затем **Настройки → Параметры разработчика → Отладка по USB**.
3. Подключите телефон кабелем, поддерживающим **передачу данных**. Разблокируйте экран и подтвердите запрос «Разрешить отладку по USB?» для своего ПК.
4. В Windows-приложении нажмите **Обновить**, выберите телефон и устройство, на котором компьютер сейчас воспроизводит звук. Нажмите **Передавать звук**. Android-приложение откроется и получит ключ подключения автоматически. Если экран заблокирован, разблокируйте его.
5. Разрешите уведомление Android: в нём можно остановить передачу, пока экран выключен. Обычная громкость регулируется кнопками телефона. Усиление отдельно включается переключателем с предупреждением.

После первого подключения можно переподключаться кнопкой **Подключиться** на телефоне, пока Windows передаёт звук. При новом запуске передачи из Windows ключ обновляется автоматически. При отключении кабеля Windows восстанавливает туннель каждые 2 секунды, Android повторяет подключение до 20 раз; затем требуется повторное подключение вручную.

При звонке, потере аудиофокуса или отключении наушников воспроизведение останавливается. Самостоятельно после такого события оно не возобновляется. Автозапуска при загрузке системы нет.

## Усиление и риск для динамика

**+12 дБ — это цифровое усиление входного сигнала, а не обещание +12 дБ акустической громкости динамика.** Тихие записи становятся громче, а пики громких записей сдерживает лимитер. Приложение не может штатным Android API обойти аппаратный предел усилителя, ограничения громкости или защиту Samsung. Регулятор телефона не поднимается автоматически.

Срез баса уменьшает нагрузку от низких частот; лимитер предотвращает превышение цифрового потолка. Но это **не гарантия физической безопасности**: программа не получает температуру звуковой катушки, ход мембраны или параметры конкретного динамика. Рост средней мощности может увеличивать нагрев, а низкие частоты — ход мембраны. При хрипе, дребезге или необычном нагреве снизьте усиление и остановите воспроизведение. Разумно начинать с +1…+3 дБ и сохранять срез баса для встроенного динамика; это рекомендация, а не измеренный безопасный предел S24.

Основание: [TI: limiter vs. Smart Amp protection](https://www.ti.com/document-viewer/lit/html/SSZT848), [TI: excursion and thermal protection](https://www.ti.com/lit/an/slaa857/slaa857.pdf). В этих источниках описаны общие механизмы защиты; они не подтверждают конкретную аппаратную схему Galaxy S24. Высокая громкость также может повредить слух: [ВОЗ](https://www.who.int/news-room/questions-and-answers/item/deafness-and-hearing-loss-safe-listening).

## Если не подключается

| Симптом | Что проверить |
|---|---|
| Телефон не найден | Кабель с передачей данных, USB-отладка, другой USB-порт. Samsung может требовать официальный USB-драйвер: [Samsung USB Driver](https://developer.samsung.com/android-usb-driver). Установщик Audio Connect драйверы системы не меняет. |
| `unauthorized` | Разблокируйте экран, подтвердите RSA-запрос USB-отладки, нажмите «Обновить». |
| ПК видит телефон, приложение не открывается | Установите APK и разблокируйте телефон. На Samsung проверьте, не блокирует ли USB-команды «Автоблокировка»; меняйте этот параметр только осознанно для своего ПК. |
| Подключено, но тихо | Проверьте медиагромкость Android и источник Windows; запустите звук в выбранном устройстве. Подключённые Bluetooth-наушники могут стать выходом Android. |
| Прерывания | Остановите передачу на телефоне, выберите буфер 80 мс, подключитесь снова. Избегайте USB-хабов с плохим питанием. |
| Звук пропал после отключения HDMI/Bluetooth на ПК | Выберите актуальный источник Windows и запустите передачу заново. |

Звук продолжает воспроизводиться и на выбранном выходе Windows. Захват отражает микшер этого выхода; защищённый DRM-контент и некоторые режимы эксклюзивного вывода могут не захватываться. Общая задержка включает WASAPI, USB и аудиотракт телефона; число буфера в интерфейсе **не является измеренной сквозной задержкой**.

Windows-установщик пока **не имеет Authenticode-подписи** коммерческим сертификатом: SmartScreen может показать «Неизвестный издатель». Берите файл только из Releases этого репозитория и проверяйте `SHA256SUMS.txt`. Приложение не требует отключать антивирус.

## Приватность

Сервер слушает только `127.0.0.1:40123`; передача идёт через `adb reverse` выбранного телефона. Беспроводные ADB-устройства и эмуляторы не показываются в обычном интерфейсе Windows. До передачи аудио клиент подтверждает случайный 256-битный ключ. Это защита от случайных подключений, не шифрование от администратора ПК, root-приложений или наблюдения за ADB. Ключ хранится в приватных SharedPreferences телефона, исключённых из резервного копирования. При новом запуске передачи ключ меняется.

Телеметрии, микрофона, удалённого управления, встроенного Telegram-токена и интернет-сервисов в приложениях нет. Windows-журнал ошибок: `%LOCALAPPDATA%\AudioConnect\app.log`, до ~1 МБ, без аудиоданных и ключей. USB-отладка даёт доверенному компьютеру расширенный доступ к телефону; отключите её после использования, если она больше не нужна.

## Сборка

Инструменты: .NET SDK 8, JDK 17, Android SDK platform 36 / build-tools 36.0.0 / platform-tools, Inno Setup 6.4+ (Windows). Версии NAudio, AGP и Gradle зафиксированы; архив Gradle проверяется SHA-256.

```powershell
dotnet build desktop/AudioConnect.Tests/AudioConnect.Tests.csproj -c Release
dotnet run --project desktop/AudioConnect.Tests -c Release --no-build
cd android
.\gradlew.bat testDebugUnitTest lintRelease assembleDebug
```

Для релиза задайте `AC_KEYSTORE`, `AC_STORE_PASSWORD`, при необходимости `AC_KEY_ALIAS` и `AC_KEY_PASSWORD`. Затем из корня:

```powershell
.\scripts\Build-Release.ps1 -AndroidSdk $env:ANDROID_HOME -Iscc 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

Результат: `dist/releases/` с установщиком, подписанным APK и SHA-256. **Не коммитьте ключ подписи или его пароль.** В GitHub Actions они хранятся в зашифрованных repository secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`). Передавайте будущие APK тем же ключом, иначе Android потребует удалить установленное приложение.

Отдельный тест реального WASAPI: `dotnet run --project desktop/AudioConnect.Tests -c Release -- --capture` (2 секунды очень тихого тестового тона). Интеграционный тест с эмулятором: задайте `AC_TEST_ADB`, `AC_TEST_SERIAL`, затем добавьте `--android`. Это тестовый инструмент, не функция обычного приложения.

## Устройство проекта

`desktop/AudioConnect.Core` — формат PCM и аутентифицированный TCP-сервер; `desktop/AudioConnect.Windows` — WPF, ADB и WASAPI; `android/app` — нативный Java UI, foreground service, AudioTrack и DSP; `installer` и `scripts` — упаковка. [Описание протокола](docs/PROTOCOL.md), [проверки релиза](docs/VALIDATION.md).

Небольшой интерфейс опирается на привычные элементы аудиоутилит: источник, состояние соединения, одна основная кнопка и буфер. В качестве примеров изучены [SoundWire](https://georgielabs.net/SoundWireHelp.html) и [AudioRelay](https://audiorelay.net/docs/usb); их оформление и код не копировались.
